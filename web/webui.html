🔀 账号调度与并发策略

配置多账号分配算法、单号并发上限及智能换号规则。
优先推荐 least-loaded，将新请求分给当前 5 小时窗口用量最低的账号，最大化利用多账号额度。
智能会话粘性 (Session Affinity / 前缀缓存保活)
同一会话优先锁定同一账号，吃满 Anthropic 官方前缀缓存 (85%+)，避免 100 万 Tokens 爆炸与 429
开启后，同一会话的多轮对话优先路由至同一账号，充分命中 Claude 上游 Prompt Cache（高达 90% 缓存命中率），大幅节省输入 Tokens 并加快响应；仅当账号额度不足、满并发或冷却时才平滑故障转移。
严格限制 3。Claude 官方免费账号上游限制并发为 3。一旦在途请求达到该值，反代自动切换至其他账号，绝不向同号硬塞。
%
当账号 5h 或 7d 窗口剩余额度低于该百分比时（默认 20%），新对话自动切到其他充足账号。
当选中账号触发 429、凭据失效或异常时，自动换下一个可用账号尝试的最大次数（默认 3 次）。
秒
当所有账号都在冷却或并发满载时，请求在反代内部排队等待账号释放的最大时长（默认 30 秒）。

🧠 上下文智能瘦身 / 防爆炸

针对编程 Agent (Codex/Cline/Claude Code 等) 历史长日志进行智能折叠，彻底防止百万 Tokens 爆炸。
启用上下文智能瘦身 (Context Pruner)
自动折叠更早轮次的超长工具输出，首尾关键代码与结构 100% 保留
多轮对话中 Agent 频繁读取长文件或终端构建日志会迅速将单次请求膨胀到十几万甚至上百万 Tokens。开启后中间冗余被优雅折叠，首尾保留率 90%，大幅度减小单次请求体。
字符
超过此长度的历史工具输出才会被折叠（推荐 8000 字符，约 2000 Tokens，可完整容纳 200~250 行代码）。保留头部 60%（导入/声明）与尾部 30%（返回值/报错摘要）。
轮
倒数最近的 N 个工具结果 100% 完整保留、绝不折叠（推荐 4 轮），确保模型对当前及上一轮的所有关键输出拥有完全精度。
